# Agent notes

Self-hostable, AI-first link shortener with device/country redirect rules and privacy-preserving click analytics. One instance serves one team. License: Apache-2.0.

- Keep code and tests simple: smallest complete change, few tests through the HTTP seam (in-process app + Testcontainers Postgres), happy path plus the edge cases that actually bite. No mocks of our own code, no tests of internals.
- Write the product name in lowercase, flitz, in all user-visible text, also at the start of a sentence, and use the words defined in `GLOSSARY.md`.
- There is no build step: Node runs the TypeScript directly, so relative imports must end in `.ts` (a `.js` import passes `tsc` and Vitest but fails in the container) and only erasable syntax is allowed (no enums, namespaces or parameter properties).
- The base schema is `packages/db/schema.sql`; keep it in sync with the Drizzle models in `packages/db/src/schema.ts`. `connectDb` installs it on an empty database in one transaction under a Postgres advisory lock, so replicas may start at once. There are no database migrations.
- Every server test file gets a freshly initialized Postgres database of its own from `testEnv()` in `apps/server/test/client.ts`. The tests of one file share them, so narrow instance-wide lists (links, domains, connected apps) before asserting on them.
- A new setting goes into the settings table in `apps/server/docs/self-hosting.md`, into `charts/flitz/values.yaml` (`secrets` if it holds a credential, else `config`) and into the shared `environment` of server and worker in `docker-compose.yml`. A setting the image sets with `ENV` needs `${VAR:-default}` there: a bare key unsets it in the container when the shell doesn't set it.
- Commit messages and releases work as `CONTRIBUTING.md` describes. Use `feat`/`fix` only for changes users notice; never edit the versions in `apps/server/package.json` and `charts/flitz/Chart.yaml` or `CHANGELOG.md` by hand: semantic-release writes them.
- Code is formatted with oxfmt (`pnpm format`, config `.oxfmtrc.json`) and linted with oxlint (`pnpm lint`, config `.oxlintrc.json`, warnings fail): fix a finding in the code rather than disabling the rule, and don't add another formatter or linter.
- New and updated dependencies must be at least 7 days old (`minimumReleaseAge` in `pnpm-workspace.yaml`): lower a range that needs a younger version instead of excluding the package from the check.
- Every shipped dependency needs a license compatible with Apache-2.0: `ua-parser-js` stays on v1 because v2 is AGPL (`.github/dependabot.yml` and `.ncurc.json` hold it back).
- `.pnpmfile.cjs` drops better-auth's optional `vitest` and `drizzle-kit` peers, which would otherwise pull vite and esbuild into the image's production install: every Dockerfile stage that runs `pnpm install` copies it.
- Import drizzle operators (`eq`, `and`, …) from `@flitzlink/db`, not `drizzle-orm`: better-auth's kysely peer makes pnpm install a second drizzle-orm copy whose types reject our schema's columns (add new operators to the re-export in `packages/db/src/index.ts`).
- Add API routes only to the `routes` registry in `apps/server/src/app.ts`, declared with `apiRoute` and their Scope: a route added with `api.openapi` directly skips authorization. The exceptions are session-only and kept out of the OpenAPI spec and MCP: users and invitations (`apps/server/src/users.ts`) and deleting deactivated links (`apps/server/src/link-deletion.ts`), both for admins in the web app; and the connected apps in `apps/server/src/connected-apps.ts` (a connection is a user's own grant, which no API Key or agent may manage). The public routes outside the registry, without Scope, are `/healthz`, `/api/domains/known`, `/api/social-providers` and `/api/auth-methods` in `app.ts`: add any new one to this list.
- Roles are set in `roleFor` (`apps/server/src/auth.ts`, called from better-auth's user-create hook, so password, magic link and social sign-ups all pass it), in the session-create hook for `ADMIN_EMAILS` and in `changeUser` (`users.ts`): never create users around better-auth, and never let a role grant access before the email is verified (an unverified user gets no session).
- Roles are read from the database on every request because better-auth's session `cookieCache` is off: don't turn it on, or a demoted or removed user keeps their access until the cached session expires.
- Redirects and QR codes read active Links from Postgres through `apps/server/src/link-store.ts`, scoped to Domain and Slug. Keep these reads uncached so edits, deactivations and deletions take effect on every replica's next request.
- Resolve a request's host only with `linkStore.resolveHost(hostname)` (the gate middleware in `app.ts` already does it and puts the result on `c.var.domain`; read that in request handlers). The Instance Domain returns null, a Custom Domain returns its row, and an unknown host gets 404.
- Cookie-authenticated `POST`/`PUT`/`PATCH`/`DELETE` routes are protected against cross-site requests only under `/api` (except `/api/auth`, which better-auth checks) and on the consent page, by `sameOriginOnly` in `app.ts`: register a new one there if a session route lives elsewhere.
- Read the client IP only with `clientIp` in `redirect-rules.ts`, never from `X-Forwarded-For`, which is trustworthy only as far as `TRUSTED_PROXIES` says. Never log or store it (the only exception is the IP better-auth records on a web app session): it may only feed the country lookup, the Visitor Hash and the rate limits (keyed by its HMAC) in memory.
- Slugs are unique per Domain: look Links up by Domain and Slug together, with `isNull(links.domainId)` for the Instance Domain (it has no `domains` row); a lookup by Slug alone mixes Domains. Build Short URLs with `shortUrl()` from `links.ts`.
- Every registry route is also served as an MCP Tool whose input merges path params, query and JSON body into one object: keep each a `z.object` with field names distinct across them, and describe input fields with `.meta({ description })`, since `.openapi()` metadata reaches the OpenAPI spec but not the MCP Tool.
- A query parameter that takes a list is `z.union([item, z.array(item)])`: Hono passes a single value as a string and a repeated one (`by=a&by=b`) as an array, and MCP Tools send list items as repeated parameters.
- `apps/web` takes API shapes from the server as `import type` of the `z.infer` types the route files export, and Scopes from the dependency-free `apps/server/src/scopes.ts`: don't retype them, and don't value-import any other server file, which would bundle server code into the SPA. The Dockerfile's `web` stage copies only `scopes.ts` from the server, so a new value import from the server must be copied there too.
- The server serves the SPA under `/app` from `apps/web/dist`, so run `pnpm build` before checking the UI through the server. Every user-visible string in `apps/web` goes through i18next (`src/locales/en.json`), and the shadcn components carry the brand-book edits (pill buttons, solid focus outline, `bg-card` fields): re-apply them after `shadcn add`.
