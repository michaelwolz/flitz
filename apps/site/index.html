Short URLs that know where to go.

A link shortener for marketing teams and app makers who want their short URLs and click stats on their own servers. Send iPhones to the App Store, Android phones to Google Play and everyone else to your website, and count every click without cookies.

Open source under Apache-2.0 · One Docker image · No cookies on short URLs · Self-hosted only

One short URL, the right place for each visitor

Redirect rules run top to bottom and the first match wins, so you can always predict where someone lands.

Device and country

Route iOS, Android, mobile and desktop visitors, or send Germany to the German page. An iPad in desktop mode looks like a Mac, so flitz answers it with a small page that sends touch screens to the iOS target.

Presets for the usual cases

App Store, mobile vs desktop and country split fill in the redirect rules, which you edit like any others. The short URL's UTM tags go to Google Play as install referrer and to the App Store as campaign token; the App Store preset adds your provider token from the instance settings.

Change it after printing

Edit targets any time. Short URLs never answer with a permanent redirect that browsers would cache, so a new target takes effect at once and repeat clicks still count.

What else flitz does

  • A QR code for every short URL

    As SVG or PNG. It encodes the short URL, not the target, so printed codes follow every change.

  • Your own domain

    Add a domain such as links.example.com, point its DNS at flitz and choose your own slugs.

  • Orphan clicks

    Requests for slugs that match no active link show you mistyped printed short URLs.

  • REST API and CSV export

    Manage links and domains and read stats with a scoped API key, or export raw clicks as CSV.

  • Users and roles

    One team per instance. Invite people as admin, member or viewer, or let everyone at your email domain sign up.

Your AI agent can run the links

Connect MCP clients that support OAuth with Client ID Metadata Documents, or use an API key. Every API operation is an MCP tool, limited by the same scopes as an API key. Agents can deactivate links but never delete them.

How connecting works

Count clicks, not people

Stats show where traffic comes from without storing who it was.

This covers short URLs and clicks. The web app sets a session cookie when you sign in and stores your IP address and browser with your session for account security; both are deleted 30 days after the session ends.

  • No cookies on short URLs. Opening a short URL stores nothing on the visitor's device.
  • IP addresses of clicks are never stored. They are used in memory for the country, unique visitors and rate limits, then dropped.
  • Unique visitors per day. Counted with a daily hash that can't be linked across days: its salt changes every day and is then deleted.
  • Bot clicks kept apart. Clicks whose user agent shows a crawler, link preview or email scanner stay out of your stats by default.

Run it yourself

flitz is self-hosted only, and no hosted version is planned. It is one Docker image that runs as server and click worker next to Postgres and Redis, started with docker compose or the Helm chart. Your links and clicks stay on your servers.

Read the self-hosting guide Source on GitHub 
git clone %REPO_URL%.git
cd flitz

# Try it locally, with a demo link at
# http://localhost:3000/x7k4m9p
docker compose --profile demo up

# Or on a server behind a TLS reverse proxy,
# which must be the only thing that can reach port 3000:
cat > .env <<EOF
BASE_URL=https://links.example.com
AUTH_SECRET=$(openssl rand -base64 32)
ADMIN_EMAILS=you@example.com
TRUSTED_PROXIES=1
SMTP_URL=smtps://user:password@smtp.example.com:465
SMTP_FROM=links@example.com
EOF
docker compose up
